Website Design System · v1.0 · July 2026

ScreenMarkPro — Marketing Website

Enterprise-grade design system for the product website — brand, visual language, tokens, components and rules

Tagline: “Draw directly on your screen. Edit everything later.” · Portable Windows 10/11 screen-annotation software for engineers, CAD designers, QA, IT, developers, trainers.

This document specifies the marketing website only (companion to the in-app UX spec). It is complete enough to build pixel-perfect without further visual decisions. Every value carries a rationale. No code.

MissionGive technical professionals the fastest way to mark up what’s on their screen — and never lose the ability to change it.
VisionScreen annotation becomes a precise, editable, engineering-grade discipline — not a throwaway red scribble.
PersonalityPrecise · calm · confident · unfussy. A senior engineer, not a salesperson. Speaks in specifics, never hype.

PositioningAbove free tools (Snipping Tool, Greenshot, ShareX) on power and precision; below/beside heavy editors (Illustrator, Snagit) on speed and price. “Illustrator-grade editing at Snipping-Tool speed.”

02 · Visual Style Direction

Chosen direction: Microsoft Fluent 2, refined with Linear’s editorial restraint. Fluent because the product is Windows-native and the audience lives in Visual Studio, Windows 11 and Office — the site should feel like an extension of their OS, not a foreign web brand. Linear’s influence adds the tight typographic rhythm, generous negative space, and dark-first sophistication that signals “premium developer tool”.

Resulting look: dark charcoal canvas, precise 1 px borders, one steel-blue accent, mica-style translucent panels used sparingly, product screenshots as the hero imagery, zero illustration. Feels like Visual Studio’s start page married to Linear’s landing page.

03 · Color System

Dark mode is primary — it matches the developer/CAD environment, makes product screenshots pop, and signals “pro tool”. Light mode is a faithful secondary for daytime/print reading. One accent (steel blue) carries all interaction; semantic colors are reserved strictly for status. Neutrals are cool-gray so the accent and screenshots stay the loudest elements.

04 · Typography

Font stack: UI/marketing text — "Segoe UI Variable", "Segoe UI", system-ui, -apple-system, sans-serif. Code — "Cascadia Code", "Cascadia Mono", Consolas, monospace. Why: Segoe is the Windows system face — the site inherits OS-native trust for free, loads instantly for the audience, and needs no webfont. Cascadia (VS/Terminal font) reinforces the developer credibility. No third font — restraint is the brand.

05 · Spacing System

Base unit 4 px, primary rhythm 8 px. 4 px gives fine control inside components (icon gaps, chip padding); 8 px and its multiples govern everything larger, so layouts stay on a predictable grid. Scale: 2 · 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128.

  • Component internal: button pad 12/24; card pad 24; input pad 10/14; chip pad 4/10.
  • Component-to-component: 16 default, 24 between distinct groups.
  • Section vertical rhythm: 96 px desktop between page sections (128 around the hero), 64 px tablet, 48 px mobile.
  • Container: max content width 1200 px; wide/full-bleed hero 1360 px; outer gutter 24 px desktop / 16 px mobile.
  • Max readable width: 720 px for prose (docs/blog/legal).
  • Vertical rhythm: heading top margin = 1.5× its line-height; paragraph gap 16 px; list item gap 8 px.

Larger containers get larger radii so the visual corner arc stays optically constant. Fully sharp corners felt harsh over screenshots; heavy rounding read consumer — this middle ramp is deliberately Windows 11.

09 · Iconography

  • Library: Fluent System Icons (Microsoft) as the base — perfect OS-native match — with Lucide as a gap-filler drawn to the same spec. One library look, never mixed styles on a page.
  • Style: outline by default (1.75 px stroke, round caps/joins, 2 px corner radius on rectangular forms). Filled variant reserved for active nav / selected states — fill = state, not emphasis.
  • Sizes: 16 (inline/label), 20 (buttons, nav), 24 (feature bullets), 32–40 (feature-card headers). Grid-aligned, 2 px safe margin.
  • Color: inherit text color; secondary text tone at rest, primary/accent on hover or when meaningful. Never multicolor.
  • Animation: none on rest; ≤120 ms color/opacity on hover only. No spinning/bouncing icons.
  • SVG rules: currentColor, viewBox 0 0 24 24, single path where possible, no baked fills, even integer coordinates.

11 · Input System

  • Text field / search / textarea: 40 h (textarea auto), surface-2 fill, 1 px border, radius 8, 14 px pad. Focus = accent border + 2 px ring. Label above (12 px overline), helper/error below (13 px). Search adds a 16 px leading icon + clear affordance.
  • Dropdown/select: matches text field; opens elevated-surface menu (elevation-2), 32 h rows, checkmark on selected, keyboard nav.
  • Checkbox: 18 px, radius 4, accent fill + white check when on; indeterminate = dash.
  • Radio: 18 px circle, accent ring + dot when on.
  • Switch: 36×20 track, radius full, accent when on, 200 ms slide; off = border track.
  • Slider: 4 px track, 16 px thumb (white + accent border), filled portion accent.
  • Validation: error = danger border + 13 px danger message + icon; success = success border + check; helper text = secondary. Never color-only — always icon + text.

15 · Animation System

Philosophy: motion clarifies, never decorates. Engineering audience distrusts flashy sites; animation is quiet, fast and functional — matching Fluent’s restraint.

  • Durations: micro (hover/press) 120 ms · UI transition 200 ms · reveal/layout 300 ms · nav/drawer 250 ms. Nothing exceeds 400 ms.
  • Easing: standard cubic-bezier(0.2,0,0,1) (Fluent-style decelerate); exits cubic-bezier(0.4,0,1,1). No bounce, no elastic.
  • Scroll reveals: fade-up 12 px, 300 ms, once, staggered 60 ms across a group. Triggered at 15% in view.
  • Micro-interactions: button lighten, card lift 2 px, icon color, chevron rotate, copy-button check-swap. All ≤ 120 ms.
  • Loading: thin accent progress bar for page transitions; skeleton shimmer (1.2 s) for async lists — never full-screen spinners.
  • Reduce motion: prefers-reduced-motion → all transforms become instant opacity fades; autoplay video → static poster; parallax off. Mandatory.

16 · Imagery

  • Product screenshots are the hero imagery — real UI, real annotations, never mockup fluff. They prove the “editable” claim better than any illustration.
  • Frames: screenshots sit in a subtle Windows-11-style window frame (title bar dot, radius 12) OR a clean 1 px border + radius 12. Consistent frame across the site.
  • Shadow: elevation-2 beneath hero shots; feature shots elevation-1. Optional accent glow only on the single hero image.
  • Perspective: flat/straight-on by default (engineering honesty). A slight 6–8° tilt allowed ONCE in the hero for depth — never repeated.
  • Backgrounds: screenshots on a dark section, optionally a faint dotted-grid or radial accent-glow backdrop (≤8% opacity). No busy gradients.
  • Zoom/hover: 1.02 scale within a clipped frame, or click → lightbox for detail. Callout pins (①②) may highlight features on hover.
  • Spacing: ≥ 48 px around framed media; captions caption-size, secondary color, 12 px below.

17 · Illustrations

No character or decorative illustrations. They would undercut the engineering-grade, professional positioning and read consumer/playful — the exact perception to avoid. Permitted instead: precise technical diagrams (architecture, editable-vector concept, offline-privacy flow) drawn in the same 1.75 px line style as the icons, monochrome + one accent, on the 8 px grid. Diagrams explain; they never decorate. Empty states use a small outline icon + one line of copy, not a scene.

18 · Accessibility

  • Standard: WCAG 2.2 AA minimum; AAA for body text where feasible (dark-mode body is 16.8:1).
  • Contrast: text ≥ 4.5:1, large text/icons/borders ≥ 3:1; never convey meaning by color alone (icon + text on all status).
  • Keyboard: full operability, logical tab order = visual order, skip-to-content link, no traps; menus/modals trap+restore focus.
  • Focus: visible 2 px accent ring + 2 px offset on every interactive element; never outline:none without replacement.
  • Screen readers: semantic landmarks, alt text on all screenshots (describe the annotation shown), aria-expanded on accordions, live regions for toasts, labelled controls.
  • Reduced motion + font sizes: honored (§15); base 16 px, rem-based, respects browser zoom to 200% without breakage.
  • Touch targets: ≥ 44×44 px on touch/tablet; ≥ 40 px on mouse.

21 · Design Rules (every page must follow)

  1. Dark mode is the default; light mode must be visually equivalent, never an afterthought.
  2. One primary (accent) button per viewport — always the download/conversion action.
  3. Accent color is for interaction and status only, never decoration.
  4. All spacing is a multiple of 4; layout spacing a multiple of 8.
  5. Body prose never exceeds 720 px width.
  6. Max 3 cards per row; feature grids collapse 3→2→1.
  7. Every interactive element has hover, focus (2 px accent ring), pressed and disabled states.
  8. Never remove focus outlines without an equivalent replacement.
  9. Status is never conveyed by color alone — always icon + text.
  10. Text contrast ≥ 4.5:1; large text/icons ≥ 3:1.
  11. Body text never below 16 px; captions never below 13 px.
  12. Only Segoe UI (Variable) for UI, Cascadia for code — no third typeface.
  13. Font weights limited to 400/500/600/700.
  14. Headings use the defined type scale — no arbitrary sizes.
  15. Radii from the ramp only (6/8/12/16/full).
  16. Borders are 1 px; dark-mode elevation via surface + border before shadow.
  17. Shadows only on floating/hover elements, from the 4-level scale.
  18. Glass/mica limited to ≤2 elements per viewport (performance).
  19. Animations ≤ 400 ms, Fluent easing, no bounce/elastic.
  20. All motion respects prefers-reduced-motion.
  21. Scroll reveals fire once, subtle (12 px fade-up), never block reading.
  22. No character illustrations, stock photos of people, or emoji.
  23. Imagery = real product screenshots in the standard frame.
  24. Every screenshot has descriptive alt text.
  25. Section vertical rhythm: 96/64/48 by breakpoint — consistent everywhere.
  26. Content aligns left to the grid; only hero/CTA centers.
  27. Sticky nav behavior is identical on every page.
  28. Comparison/feature copy uses specifics and numbers, not adjectives.
  29. Tone: direct, technical, no hype, no exclamation marks.
  30. Keyboard-shortcut chips use the standard kbd component.
  31. Touch targets ≥ 44 px; mouse targets ≥ 40 px.
  32. Only semantic tokens in components — never raw hex.
  33. Icons from one library, one style per page, currentColor.
  34. Filled icons signal active state; outline is default.
  35. Trust signals (offline · portable · no-login · no-telemetry) appear above the fold.
  36. Download component always shows version, size and checksum.
  37. Every page reachable in ≤2 clicks from the nav.
  38. No autoplaying audio; video muted + reduce-motion aware.
  39. Tables scroll horizontally on mobile, never shrink text below 13 px.
  40. Empty/error states use icon + one sentence, never a scene.
  41. Whitespace is a feature — when in doubt, add space, not elements.
  42. Every new component must map to existing tokens before shipping.

Governance: any new page is assembled only from documented components and semantic tokens; a new component enters the library only after it is specified to this document’s depth (anatomy, states, tokens, rationale). This keeps eight future surfaces visually identical to launch day.

End of website design system. Companion to the ScreenMarkPro in-app UX specification. Together they define product and marketing under one visual language: Fluent-native, engineering-grade, dark-first.
