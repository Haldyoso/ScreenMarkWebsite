UX Design Specification · v1.0 · July 2026

ScreenMarkPro

Complete UX redesign of a portable Windows 10/11 screen-annotation tool for engineering professionals

Scope: full product — information architecture, interaction design, panels, menus, design system, component library, wireframes, rationale, roadmap. Every existing feature is preserved and reorganized; nothing is removed.

Audience: designers building high-fidelity Figma mockups and engineers implementing the shell. Target users: mechanical engineers, CAD designers (CATIA / NX / Creo), QA inspectors, manufacturing engineers, technical writers, trainers, IT support.

01 · Product Philosophy

ScreenMarkPro competes on time-to-annotation, not feature count. Users live in CAD software for 8+ hours a day; annotation is an interruption of their real work. Every design decision below is measured against one number: seconds from intent to exported image. The philosophy in one line: Open → Draw → Export, with zero ceremony.

Seven principles

  1. Speed first, always. Every core action (pick tool, draw, export) is reachable in ≤1 click or 1 keystroke. No modal dialogs on the critical path. Export to clipboard is a single keystroke (Ctrl+C).
  2. Keyboard-first, mouse-equal. Every tool has a single-letter shortcut (CAD muscle memory: A = Arrow, R = Rectangle). Shortcuts are printed in every tooltip and every menu row — the UI teaches its own shortcuts.
  3. Progressive disclosure. The default surface shows ~12 controls. Everything else (layers, history, advanced properties, settings) lives one deliberate step away and never opens on its own. Novices see a simple tool; experts unlock depth without switching apps.
  4. Direct manipulation, editable forever. Objects behave like PowerPoint/Illustrator objects: select, drag, resize, rotate in place. Properties change live with no Apply button. Nothing is ever rasterized until export.
  5. Native Windows feel. Fluent-adjacent visuals, Segoe UI Variable, standard Windows conventions (F1 help, F2 rename, Esc cancels, right-click menus, Alt-key access). No web-app chrome, no splash screens, no onboarding tours.
  6. Consistency and predictability. One properties model, one selection model, one color picker, one context-menu grammar used everywhere. The same action never lives in two inconsistent places.
  7. Zero-distraction canvas. The screen being annotated is the workspace. UI floats above it, is draggable, collapsible, and auto-dodges the cursor during drawing. No animations longer than 150 ms; no decoration that costs attention.
Success metrics (design targets)
  • Launch → first stroke: < 2 s
  • Annotate 3 callouts + export to clipboard: < 15 s
  • All 22 tools reachable without opening any menu
  • 100% of features discoverable via search in Help (F1)

Placement rules

  • Toolbar defaults to top-center of the active monitor, remembers position per monitor, snaps to edges, and auto-nudges away if the user draws underneath it.
  • Properties appears only when something is selected (or a tool with options is armed). Default: compact floating card near the selection; can be pinned into a docked inspector on the right edge.
  • Side rail (Layers/History) is hidden by default — toggled with L-key panel toggle (Ctrl+L / Ctrl+H) or via app menu. It never opens automatically.
  • Export is a split button: click = repeat last export (e.g. "PNG to clipboard"); the chevron opens destinations; Ctrl+Shift+E opens the full dialog.
  • Settings and Help are reachable only from the app menu (☰) and F1 — they are off the critical path by design.

03 · User Flows

Steps are annotated with clicks (🖱) and keystrokes (⌨). Target counts assume a practiced user.

3.1 Quick annotation (the hero flow — ≤ 6 actions)

  1. ⌨ Global hotkey (default Ctrl+Shift+D) → overlay activates on current monitor, toolbar fades in (100 ms), last-used tool is pre-armed.
  2. ⌨ A → Arrow tool. 🖱 Drag arrow onto the defect.
  3. ⌨ T → Text. 🖱 Click; type label. Enter commits.
  4. ⌨ Ctrl+C → flattened PNG on clipboard. Toast: “Copied · 1920×1080”.
  5. ⌨ Esc → overlay dismisses (annotations kept in session for re-entry).

3.2 Screenshot review

User pastes or opens an image (Ctrl+V / drag onto canvas / ☰ → Open image). Image becomes a locked background layer. Annotate as in 3.1. Pan with Space-drag, zoom with Ctrl+wheel (25–800%, zoom readout in toolbar). Export respects original image resolution, not screen resolution.

3.3 QA inspection

  1. Freeze screen (F in overlay or global hotkey) so live gauges can’t change mid-markup.
  2. Number markers (N): each click drops an auto-incrementing badge ①②③. Style set once, reused.
  3. OK / NOK stamps (K / Shift+K): one click each; stamps snap to a uniform size.
  4. Blur (B) over serial numbers / operator names.
  5. Export dialog → “Selection region → PNG” for the report, then Ctrl+S to keep the .smp.json project as the audit trail (annotations stay editable for re-inspection).

3.4 CAD review

Freeze the CATIA/NX viewport. Use Arc (3-point) and Angle measurement — both use CAD-style input: click 1 = start, click 2 = end, click 3 = bulge/vertex; a live readout follows the cursor (radius / angle in °, 1 decimal). Focus rectangle dims everything except the flange under discussion. Measurements are objects: re-selectable, re-styled, deletable — never burned in.

3.5 Presentation / training mode

Toolbar collapses to a pill (double-click drag handle or Ctrl+.). Pen and Highlighter strokes optionally auto-fade after 3 s (toggle in tool options). Number markers guide “step 1, step 2…”. Whiteboard (W) / Blackboard (Shift+W) switch the canvas for sketching sessions; annotations persist per mode so switching back restores the desktop markup.

3.6 Freeze mode

Freeze captures all monitors as static bitmaps. A thin accent border + “FROZEN” chip on the toolbar are the only indicators. Multi-monitor: each screen freezes independently; toolbar migrates with the cursor. Unfreeze (same key) keeps annotations floating over the live screen; a divergence warning chip appears if the screen content changed underneath.

3.7 Editing existing objects

  1. ⌨ Esc or V → Selection tool (also: any object is click-selectable while a drawing tool is armed, via Ctrl+click).
  2. Click = select (8 handles + rotation handle). Drag = move. Shift-drag = axis-locked. Handles resize; Shift preserves aspect; Alt resizes from center. Arrow keys nudge 1 px, Shift+arrows 10 px.
  3. Double-click text → inline edit. Double-click shape → edits its label if any, else opens Properties.
  4. Properties card follows the selection; every control is live.

3.8 Grouping

Marquee or Shift-click multi-select → Ctrl+G. Group acts as one object (move/scale/rotate together). Double-click enters the group (breadcrumb chip “Group 3 ▸” appears; Esc exits). Ctrl+Shift+G ungroups. Groups nest; the Layers tree shows hierarchy.

3.9 Export

  • Ctrl+C — flattened image of current monitor to clipboard (zero dialogs).
  • Ctrl+E — repeat last export exactly (same format, region, destination, filename pattern).
  • Ctrl+Shift+E — Export dialog: region (Selection / Visible / Monitor n / All monitors), format (PNG / transparent PNG / JPG q-slider), destination (Clipboard / File / Folder with auto-name pattern {date}_{time}_{n}), scale (1×/2×). Live preview thumbnail. Remembers everything.

3.10 Project saving

Ctrl+S saves .smp.json (vector objects + embedded background captures) next to the portable exe by default. Title chip in the toolbar shows filename + dirty dot (●). Ctrl+O / drag a .smp.json onto the overlay reopens with full editability.

3.11 Recovery after crash

Autosave writes a rolling snapshot every 30 s (and on every export) to ./autosave/. On next launch after an unclean exit, a single non-modal toast offers: Restore session (n objects, 14:32) · Discard. No blocking dialog; ignoring the toast starts fresh while keeping the snapshot for 7 days.

Behavior specification

  • Sizes. Large mode: 40×40 px buttons, 20 px icons. Compact mode: 32×32 px, 16 px icons (auto below 1366 px width, or user toggle). Toolbar height 48 / 40 px, radius 8 px, elevation-3 shadow.
  • Drag handle (⋮⋮, 12 px wide) at the left end; whole empty toolbar surface also drags. Snaps to screen edges at 16 px threshold; docks vertically on left/right edges (icons re-stack).
  • Hover: 100 ms background tint; tooltip after 500 ms — name + shortcut + one-line hint (“Arrow — A · Shift locks to 45°”). No hover animation beyond tint.
  • Active tool: accent-filled background + white icon; exactly one tool active at all times.
  • Overflow (»): when width-constrained, groups collapse right-to-left (Actions never collapse) into a » menu that preserves group headers. Nothing is ever hidden without the » indicator.
  • Collapse: double-click drag handle or Ctrl+. → 48 px pill showing app glyph + active-tool icon. Click or any tool shortcut expands. Auto-collapse option during drawing.
  • Priority order (left→right) mirrors frequency: selection > drawing > callouts > effects > style > actions. Export sits at the far right where the flow ends — matching the mental model draw → finish → export.

Interaction rules

  • Live updates: every control applies on input (slider drag, keystroke in numeric field after 150 ms debounce). No Apply/OK. One undo step per committed gesture, not per pixel.
  • Multi-selection: shared values show normally; mixed values show “—” (em-dash placeholder); editing writes the value to all. Sections not common to all selected types collapse with a “applies to 3 of 5” caption.
  • Disabled ≠ hidden: a control that exists for the type but is currently inapplicable (corner radius on a sharp rect style) renders at 40% opacity with a tooltip explaining why. Sections that never apply to the type are omitted entirely.
  • Numeric fields: drag label to scrub; ↑/↓ ±1, Shift ±10, Alt ±0.1; accepts simple math; Tab order left→right, top→bottom.
  • Color pickers: one shared popover everywhere — 16 engineering palette swatches, 8 recents, HSV field, hex input, eyedropper (samples the frozen screen). Alpha only where fill/stroke supports it.
  • Tool options preview: when a tool is armed with nothing selected, the panel shows that tool’s defaults — edits set the defaults for the next object (Illustrator model).

06 · Layers Panel

A flat-by-default object list (newest on top) that becomes a tree only where groups exist — Figma’s model, not Photoshop’s heavyweight layers. Lives in the side rail, 260 px wide.

  • Row anatomy (28 px): disclosure caret (groups only) · type glyph · name (auto “Arrow 3”, F2/double-click renames) · hover-revealed 👁 visibility and 🔒 lock icons (persist when active).
  • Hierarchy: groups indent 16 px, nest arbitrarily; background captures live in a pinned “Background” section at the bottom, locked by default.
  • Selection sync is bidirectional: canvas click highlights the row (auto-scrolls into view via list scroll); row click selects on canvas; Ctrl-click adds; Shift-click ranges. Hover on a row shows a subtle outline on the canvas object.
  • Drag ordering: rows drag with a 2 px accent insertion line; dragging onto a group row (200 ms hover) drops inside it. Alt-drag duplicates.
  • Search field at top filters by name and by type keyword (“arrow”, “text”, “blur”); matches shown flat with a “in Group 2” breadcrumb caption. Esc clears.
  • Bulk affordances: header buttons — hide/show all, lock/unlock all, delete hidden. Right-click on rows opens the same object context menu as the canvas (one grammar).

07 · History Panel

Second tab of the side rail. A vertical timeline of named actions, newest at top.

  • Naming grammar: verb + object — “Draw Arrow”, “Move 3 objects”, “Change stroke color”, “Group (4)”, “Delete Text 2”, “Import image”. Continuous gestures coalesce into one entry.
  • Current state marker: filled accent dot + bold row. Entries above it (undone states) render at 45% opacity — visibly “in the future”, still reachable.
  • Jump to state: single click any entry → canvas restores instantly (<100 ms; internally batched undo/redo). Redo branch is linear: acting from a past state discards the grayed future (a one-time hint toast explains this the first time).
  • Capacity: 200 steps default (50–500 in Settings); oldest coalesce into a “Session start” baseline entry. Undo/redo buttons and Ctrl+Z/Ctrl+Y always work without the panel open.
  • Visual indicators: each row = 26 px: state dot · action icon (matches tool glyph) · label · time (“14:32”) on hover. Export/save events appear as thin milestone dividers, not steps.

12 · Iconography

  • Style: Fluent-adjacent outlined glyphs, original artwork. 20 px grid (toolbar), 16 px (panels, menus), 2 px safe margin.
  • Stroke: 1.5 px at 1×, round caps and joins, corner radius 1 px on rectangular forms. Strokes align to the half-pixel so they render crisp at 100/125/150/200% DPI.
  • Outlined vs filled: outlined = rest state; the same glyph with filled interior = active/selected state (tool armed, tab selected). Never mix metaphors — fill signals state, not importance.
  • Optical balance: normalize visual weight, not bounding box — circles/diamonds overshoot the grid by 0.5 px; dense glyphs (blur, layers) drop interior detail below 16 px rather than thinning strokes.
  • Tool icons literal, not abstract: arrow tool = an arrow, blur = dotted mosaic square, angle = two rays + arc with “°”. A CAD user must identify every tool without reading its tooltip.
  • SVG guidelines: single path per glyph where possible, stroke="currentColor", no embedded fills/colors, viewBox 0 0 20 20, exported at even integers. Naming: ic-{name}-{16|20}{-filled}.

14 · Accessibility

  • Keyboard: 100% of functionality without a mouse. F6 cycles surfaces (toolbar → properties → rail → canvas); Tab/arrows within a surface; Esc always steps back one level (edit → selection → tool → dismiss overlay). Object traversal: Tab/Shift+Tab cycles objects in z-order; arrows nudge; Enter edits.
  • Screen readers: UI Automation on every control; tools announce “Arrow tool, A, selected”; canvas objects expose name, type, position (“Arrow 3, 240 by 60, at 410, 220”); toasts are live regions; history announces the restored state.
  • Focus order follows visual order; focus ring only on keyboard focus; focus returns to the invoking control when menus/dialogs close.
  • Contrast: AA (4.5:1) for text, 3:1 for icons/borders in both themes; selection visuals never rely on color alone (handles + bounds shape). High-contrast Windows themes map tokens to system colors.
  • Targets: minimum 32×32 px hit area (handles get invisible 12 px padding); compact mode keeps 32 px hits under 24 px visuals.
  • High DPI & scaling: per-monitor DPI v2; UI scales with system setting; icons ship as SVG; stroke snapping keeps hairlines crisp at 100–300%.
  • Multi-monitor: panels remember per-monitor positions, never open off-screen; toolbar follows cursor across monitors on freeze; mixed-DPI setups render each surface at its own scale.
  • Motion & input: honors “reduce motion” (fades → instant); all drags have keyboard equivalents; sticky-keys-safe chords only.

16 · Design Rationale

Decision Problem it solves & comparison
Grouped toolbar with flyouts (12 slots for 22 tools)Kills the crowding without hiding features. Illustrator proved the last-used-face flyout for 30 years; ShareX buries tools in nested menus (slow); Snipping Tool has too few tools to matter. Fitts’ law: 12 large targets beat 24 tiny ones.
Shortcuts printed everywhereFixes discoverability of the existing shortcut wealth. Figma teaches shortcuts via tooltips/menus and its users convert to keyboard use measurably faster than Greenshot’s, which hides them in docs.
One properties inspector, contextual card + optional dockEnds “properties in multiple places”. PowerPoint splits format between ribbon, pane and mini-toolbar — users hunt; Figma’s single right panel is the model. The floating card keeps the fast path light; pinning serves the CAD dual-monitor habit.
Layers hidden by default80% of sessions are 5 objects or fewer — a permanent tree is noise (Illustrator’s weakness for light tasks). It exists for the 20%: QA reports with 30 markers. Snipping Tool/Greenshot have no object model at all — our differentiator stays discoverable via context menu + Ctrl+L.
Split-button export + Ctrl+E repeatExport is the most repeated action; ShareX’s after-capture-task idea is right but its config maze is wrong. One click repeats the whole last export; the dialog exists once, then gets out of the way. Greenshot asks destination every time — we never ask twice.
Named, clickable historyBlind Ctrl+Z roulette becomes visible time travel. Illustrator/Photoshop history panels prove jump-to-state; PowerPoint and all screenshot tools lack it. Critical for QA: “go back to before I moved the markers”.
One context-menu grammarFixes “inconsistent interactions”: identical section order everywhere means spatial memory works — Delete is always last, Group always in block 3. Windows 11 menu redesign follows the same logic.
Dark, semi-opaque overlay UIThe UI must read over any desktop — dark surfaces at 96% with hairline borders stay legible on white docs and dark CAD viewports alike; Snipping Tool’s light chrome washes out on bright content.
CAD-style 3-point arc & live measurement readoutsMatches CATIA/NX input muscle memory instead of forcing bezier handles (Illustrator’s model is wrong for this audience). Measurements as editable objects = audit-friendly, unlike burned-in pixels in every screenshot tool.
No main window, 3 dialogs totalPreserves “Open → Draw → Export”. Every dialog is a tax on the hero flow; ShareX has ~40 windows, we have 3, and none appear uninvited (crash recovery is a toast, not a modal).

17 · Future UX Roadmap

v1.0 — ship the redesign

  • Everything in this document: grouped toolbar, unified inspector, side rail, context-menu grammar, export split-button, dark/light themes, full keyboard map, crash-recovery toast.
  • Shortcut customization (Settings ▸ Shortcuts) — table with conflict detection, export/import as JSON (portable-friendly).

v1.1 — workflow accelerators (no new surfaces)

  • Style presets: save named tool styles (“QA red arrow 6 px”), applied from the style well; 1–9 keys map to them.
  • Smart guides: alignment/spacing snap lines between objects (PowerPoint-style), toggleable.
  • Dimension line tool (extension of angle measurement): pixel/mm distance with calibration.
  • Quick-command palette (Ctrl+K): type any command/tool name — search UI already exists in Help.

v2.0 — team & scale (still portable, still offline)

  • Multi-page projects: one .smp.json holds several annotated captures (inspection series); page strip appears only when pages > 1.
  • Template stamps: org-defined reusable groups (title block, inspection header) loaded from a shared folder — no cloud.
  • PDF export (multi-page) and SVG export for documentation pipelines.
  • Annotation diff view: compare two saved projects of the same capture — QA re-inspection use case.

Anti-bloat rule for every future feature: it must not add a permanent surface, must not add a dialog to the hero flow, and must be reachable by keyboard. If it fails any test, it doesn’t ship. — End of specification.
